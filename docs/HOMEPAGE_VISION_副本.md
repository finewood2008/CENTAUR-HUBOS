# Hub OS 首页愿景：多智能体协作平台

> 2026-04-20 | 产品方向思考文档
> 状态：讨论稿，待确认

---

## 一、核心思路

把 Hub OS 首页从"合伙人对话界面"升级为 **Discord 风格的多智能体协作平台**。

一句话定位：**用户的 AI 管家指挥中心**。

用户不需要知道后面有几个智能体、它们各自擅长什么。用户只跟一个"管家"对话，管家负责理解需求、拆解任务、分配给合适的智能体、跟进进度、汇总结果。

---

## 二、为什么要做这个转变

### 现状的问题

1. **当前首页是"对话+看板"**——像一个高级聊天窗口，缺乏"团队协作"的感觉
2. **智能体之间的协作不可见**——用户看不到任务被分配、执行、完成的过程
3. **用户要自己决定"找谁做什么"**——需要了解每个员工的能力边界，心智负担重
4. **缺少任务的生命周期管理**——发出去的指令没有状态跟踪

### 转变后的价值

1. **降低用户门槛**——只跟管家聊，不需要了解各智能体
2. **透明的任务流转**——看得见任务是怎么被拆解、分配、执行的
3. **团队协作感**——多个智能体像真实团队一样协同工作
4. **结果导向**——管家汇总结果，用户一站式获取

### 3.2 管家的核心能力

| 能力 | 说明 | 类比 |
|------|------|------|
| 意图理解 | 用户说"帮我搞个活动"，管家理解成品牌设计+文案+渠道推广 | 项目经理 |
| 任务拆解 | 一个大需求拆成多个子任务，分配给不同智能体 | 技术Lead |

| 冲突协调 | 多个智能体输出不一致时进行协调 | 架构师 |
| 主动汇报 | 不需要用户追问，主动推送进展 | 秘书 |

## 四、UI 设计方向

### 4.1 借鉴 Discord 的核心理念，但不照搬

Discord 做对了什么：
- **Channel 概念**——不同话题有不同频道，信息有序
- **在线状态**——一眼看出谁在线、谁在忙
- **消息流**——实时、流动、有温度
- **@提及**——精准调度某个角色

我们不照搬什么：
- 不搞多频道切换——用户只需要一个主对话窗口（跟管家的）
- 不搞群聊——不是多人聊天室，是管家指挥中心
- 不搞服务器/频道层级——太复杂，中小企业用不上

### 4.3 三栏设计说明

#### 左栏：团队侧栏（~200px）

- **管家头像**置顶，显示名字和在线状态
- **各智能体列表**，显示：
  - 头像 + 名字
  - 实时状态（在线/工作中/空闲/离线）
  - 当前正在做什么（一行文字）
- 点击某个智能体 → 不是跟它直接聊，而是在主对话区告诉管家"我想了解XX的情况"
- 底部可以有"添加新员工"入口

#### 中栏：主对话区（~60%）

这是核心交互区。跟 Discord 的消息流类似，但有几个特殊设计：

- **只跟管家对话**——用户发消息，管家回复
- **管家可以"转述"智能体的话**——管家说"火花那边出了初稿，你看看"，然后嵌入火花的产出
- **富内容嵌入**——不只是文字，可以嵌入：
  - 设计方案预览卡片
  - 数据报表摘要
  - 审批操作按钮
  - 任务进度条
  - 文件/文档预览
- **任务可视化**——管家分配任务时，显示一个任务卡片，实时更新状态
- 输入框支持 @提及（提示管家优先让某个员工处理）

#### 右栏：任务面板（~280px）

- **进行中的任务**——每个任务显示：
  - 哪个智能体在做
  - 做了多久
  - 进度（如果可量化）
  - 预计完成时间
- **待审批的事项**——需要用户确认的
- **今日已完成**——收起来的完成列表
- 可以折叠，给主对话区更多空间

## 六、与现有架构的关系

### 保留什么

1. **5个数字员工的定义**——火花/小可/书熙/税宝/绿安，角色定位不变
2. **合伙人"阿拓"的概念**——升级为"管家"，能力更强
3. **消息数据模型**——ChatMessage / MessageAttachment 的类型基本够用
4. **团队页面**——作为智能体详细配置的入口，从首页团队侧栏可以跳过去

### 需要改什么

| 现状 | 目标 | 改动量 |
|------|------|--------|
| 左右两栏（对话+侧面板） | 三栏（团队+对话+任务） | 重构Cockpit布局 |
| 侧面板是"汇报+看板" | 右栏变成"任务面板" | 重构SidePanel |
| 团队成员条在对话区顶部 | 独立的团队侧栏 | 抽出TeamBar为独立组件 |
| 管家只是简单回复 | 管家有任务拆解/分配/汇总能力 | 后端逻辑（MVP可先mock） |
| 没有任务状态系统 | 完整的任务生命周期 | 新增TaskBoard组件+数据模型 |

### 新增什么

1. **TaskBoard 组件**——任务面板，显示进行中/待审批/已完成
2. **Task 数据模型**——任务的生命周期（创建→分配→执行中→待审批→完成）
3. **TeamSidebar 组件**——左侧团队栏，显示各智能体状态
4. **任务卡片组件**——在对话流中嵌入的任务进度卡片
5. **管家路由逻辑**——根据用户输入判断应该交给哪个智能体（MVP阶段mock）

## 八、跟外部Channel的关系

用户目前通过多个渠道跟管家沟通：
- Hub OS 网页端（这个首页）
- 企业微信
- 飞书
- Telegram
- ...

所有 Channel 都连到同一个管家。Hub OS 首页是"全功能版"——有任务面板、团队状态、富内容展示。其他 Channel 是"轻量版"——纯对话，管家用文字描述任务进度。

```
                    ┌─── 企微 ───┐
                    │            │
Hub OS 首页 ──────→ │   管家核心  │ ←── 飞书
 (全功能)           │   (阿拓)   │      (轻量)
                    │            │
                    └─── TG ────┘
                         (轻量)
```

首页的独特价值：**可视化**。在企微里你只能看到文字，但在首页你能看到任务面板、进度条、团队状态、设计稿预览……这是用户打开 Hub OS 的理由。

## 九、待讨论的问题

1. **管家的名字**——继续叫"阿拓"还是让用户自己取名？还是默认叫"管家"更直白？
2. **智能体之间能不能直接对话**——目前设计是管家统一调度，智能体之间不直接交流。要不要开放这个？
3. **任务的粒度**——"帮我写篇文章"算一个任务还是拆成"拟大纲→写初稿→配图→排版"多个子任务？
4. **用户能不能绕过管家直接找某个智能体**——点团队侧栏的员工能不能跳到直接对话？
5. **右侧任务面板的信息密度**——放多少信息合适？会不会太重？
6. **移动端适配**——三栏布局在手机上怎么处理？

## 十、总结

这个方向的本质是：**把"数字员工团队"这个概念产品化**。

现在的首页像是"跟一个AI聊天"。改完之后，用户的感受是"我在管理一个AI团队"。管家是那个帮你省事的人——你只要说一句话，他就帮你安排好一切，你只需要在关键节点做决策。

这比单纯的"AI对话"有更强的产品力和付费意愿。企业老板买的不是"一个AI"，是"一个团队"。
